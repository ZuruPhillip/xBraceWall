## 1 概述

### 1.1 编写目的

本手册指导操作人员从零创建 CncWallStation 系统所需的 MySQL 业务库 `DcwCncStation`，包括数据库、8 张业务表、全部索引与外键、EF Core 迁移历史基线，并提供可执行的校验与故障排查方法。

### 1.2 数据库结构来源

库结构不是凭经验手写的，而是由代码模型严格推导，保证与应用写入逻辑一致：

| 来源 | 作用 |
| --- | --- |
| `CncWallStation/appsettings.json` → `ConnectionStrings:Default` | 唯一权威连接信息（服务器、端口、库名、账号） |
| `CncWallStation/Migrations/AppDbContextModelSnapshot.cs` | 当前模型最终状态，是全量 DDL 的生成依据 |
| `CncWallStation/EntityFrameworkCore/AppDbContext.cs` | 索引名、默认值、级联删除、`MEDIUMTEXT` 等细节配置 |
| `CncWallStation/Migrations/2026*_*.cs` | 已有 3 个增量迁移，用于建立迁移历史基线 |
| `CncWallStation/Services/Application/DatabaseInitializerHostedService.cs` | 应用启动时的兜底建表逻辑，受 `Database:AutoInitialize` 开关控制（见第 7 章） |

### 1.3 适用范围与限制

- 本手册适用于**全新空库**的创建，也适用于对已存在库做幂等重复执行（脚本不会删表、不会清数据）。
- 若目标库已有业务数据且结构较旧，请勿直接执行本手册，需先按第 10 章备份，再由开发确认升级路径。
- 迁移历史基线建立后，**不要对该库执行 `dotnet ef database update`**，原因见 6.3。

## 2 环境与前置条件

### 2.1 目标数据库信息

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 主机（IP） | `10.33.120.30` | 以现场交付的 `appsettings.json` 为准 |
| 端口 | `3306` | 默认实例端口 |
| 数据库名 | `DcwCncStation` | 区分大小写，请勿写成 `DcwCNCStation` |
| 字符集 | `utf8mb4` | 必须，否则中文/生僻字与 emoji 会写入失败 |
| 排序规则 | `utf8mb4_0900_ai_ci` | 与该服务器同级库（如 `ShutteringStation`）保持一致 |
| 存储引擎 | `InnoDB` | 外键与事务依赖 |
| 账号 | `root`（当前配置） | 生产环境建议按 2.4 创建专用账号 |

> **安全提示**：密码不在本手册中明文记录。请从 `CncWallStation/appsettings.json` 的 `ConnectionStrings:Default` 获取，或向现场 DBA 索取。严禁将密码写入工位机的文本文件、聊天记录或工单截图。

### 2.2 客户端工具与版本要求

| 工具 | 最低版本 | 用途 |
| --- | --- | --- |
| `mysql` 命令行客户端 | 5.7 及以上（推荐 8.0） | 执行脚本、校验 |
| MySQL Workbench / Navicat / DBeaver | 任意较新版本 | 图形化执行脚本、查看结构 |
| .NET SDK | 8.0 | 仅方式三（EF Core 命令）与运行程序需要 |
| `dotnet-ef` 工具 | 8.0.10 及以上 | 仅方式三需要 |

Windows 下 `mysql.exe` 常见路径：`C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe`。可先确认：

```powershell
mysql --version
```

### 2.3 连通性检查

执行任何脚本前，必须先确认网络可达，避免"连接超时"被误判为脚本错误。

```powershell
# Windows PowerShell：检查 3306 端口是否开放
Test-NetConnection -ComputerName 10.33.120.30 -Port 3306
```

```bash
# Linux / 服务器本机
nc -zv 10.33.120.30 3306
```

再确认账号可登录（交互式输入密码，不在命令行明文写密码）：

```powershell
mysql -h 10.33.120.30 -P 3306 -u root -p -e "SELECT @@hostname, @@version, @@character_set_server;"
```

> 若未开启 `skip_name_resolve`，MySQL 会反查客户端主机名，首次连接可能等待 10～15 秒甚至超时；重试一次通常即可成功。本系统 `DatabaseInitializerHostedService` 内置了同样的重试策略（2 秒、5 秒后各重试一次）。

### 2.4 账号权限要求

建库账号至少需要以下权限：

| 权限 | 用途 |
| --- | --- |
| `CREATE` | 创建数据库与表 |
| `ALTER` | 后续结构升级 |
| `INDEX` | 创建索引 |
| `REFERENCES` | 创建外键 |
| `CREATE TEMPORARY TABLES` | EF Core 部分场景使用 |
| `SELECT` / `INSERT` / `UPDATE` / `DELETE` | 业务读写 |

生产环境建议改用专用账号（由 DBA 执行以下语句，密码按现场规范替换）：

```sql
-- 在服务器上以 root 执行
CREATE USER IF NOT EXISTS 'dcw_app'@'%' IDENTIFIED BY '<强密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES, CREATE TEMPORARY TABLES
    ON `DcwCncStation`.* TO 'dcw_app'@'%';
FLUSH PRIVILEGES;
```

改为专用账号后，需同步修改 `CncWallStation/appsettings.json` 的 `ConnectionStrings:Default`。

> 注意区分两类权限：上表是**建库账号**（执行本手册 SQL 时使用）所需的最小集合。程序的**运行账号**在 `Database:AutoInitialize=false`（当前交付值）时**不需要** `CREATE` / `ALTER` / `INDEX` / `REFERENCES`，只保留 `SELECT` / `INSERT` / `UPDATE` / `DELETE` 即可（见 7.3）。

## 3 交付脚本清单与执行顺序

全部脚本位于仓库 `documents/sql/` 目录，**必须按序号顺序执行**。

| 序号 | 脚本文件 | 作用 | 幂等 | 可重复执行 |
| --- | --- | --- | --- | --- |
| 01 | `01_create_database.sql` | 创建 `DcwCncStation` 库（utf8mb4 / utf8mb4_0900_ai_ci） | 是 | 是 |
| 02 | `02_schema_full.sql` | 创建 8 张业务表（含索引、外键、默认值） | 是 | 是 |
| 03 | `03_migration_history_baseline.sql` | 创建 `__EFMigrationsHistory` 并登记 3 个已有迁移 | 是 | 是 |
| 04 | `04_verify.sql` | 结构校验（库字符集、表数量、索引、外键、默认值、基线） | 只读 | 是 |
| 05 | `05_drop_database.sql` | 删除整个库（**危险，仅作回滚参考，默认不执行**） | 是 | 否（勿随意执行） |

执行顺序：

```
01_create_database.sql  →  02_schema_full.sql  →  03_migration_history_baseline.sql  →  04_verify.sql
```

**失败即停原则**：任一脚本报错立即终止，不要继续执行后续脚本。半成品库状态（部分表缺失、索引不全）比空库更难排查。

## 4 方式一：命令行脚本一键建库（推荐）

### 4.1 Windows（PowerShell）

在仓库根目录 `DCW/` 下打开 PowerShell：

```powershell
# 1) 以环境变量传递密码，避免出现在命令行历史与进程列表中
$env:MYSQL_PWD = Read-Host "请输入 MySQL 密码" -AsSecureString |
    ForEach-Object { [Runtime.InteropServices.Marshal]::PtrToStringAuto(
        [Runtime.InteropServices.Marshal]::SecureStringToBSTR($_)) }

# 2) 建库
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 `
      -e "source d:/Works/workspace/projects/WorkStations/xBraceWall/DCW/documents/sql/01_create_database.sql"

# 3) 建表
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation `
      -e "source d:/Works/workspace/projects/WorkStations/xBraceWall/DCW/documents/sql/02_schema_full.sql"

# 4) 迁移历史基线
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation `
      -e "source d:/Works/workspace/projects/WorkStations/xBraceWall/DCW/documents/sql/03_migration_history_baseline.sql"

# 5) 校验
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation `
      -e "source d:/Works/workspace/projects/WorkStations/xBraceWall/DCW/documents/sql/04_verify.sql"

# 6) 清理密码环境变量
Remove-Item Env:MYSQL_PWD
```

> 注意：`mysql -e "source ..."` 一次只能带一个 `source`，不要把多个 `source` 用分号拼在同一条 `-e` 里。

### 4.2 Linux / macOS（bash）

```bash
cd /path/to/DCW/documents/sql

read -s -p "MySQL 密码: " MYSQL_PWD; export MYSQL_PWD

mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 < 01_create_database.sql
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation < 02_schema_full.sql
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation < 03_migration_history_baseline.sql
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation < 04_verify.sql

unset MYSQL_PWD
```

若提示 `ERROR 1045 (28000): Access denied`，见第 9 章。

### 4.3 一次性合并执行（可选）

需要转交他人执行时，可把 01～03 合并为单文件（顺序不能变，否则外键创建失败）：

```powershell
Get-Content 01_create_database.sql, 02_schema_full.sql, 03_migration_history_baseline.sql |
    Set-Content -Encoding utf8 all_in_one.sql
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation -e "source all_in_one.sql"
```

> 合并后仍需单独执行 `04_verify.sql` 做校验。

## 5 方式二：图形化客户端建库

以 MySQL Workbench 为例：

1. **新建连接**：`Database` → `Manage Connections`，Hostname 填 `10.33.120.30`，Port `3306`，Username `root`，`Store in Vault` 输入密码，Test Connection 通过后保存。
2. **打开 SQL 编辑器**：连接建立后点击 `File` → `Open SQL Script`，打开 `documents/sql/01_create_database.sql`。
3. **执行建库**：点击闪电图标（Execute），或 `Ctrl+Shift+Enter` 全量执行。确认结果集显示 `DcwCncStation | utf8mb4 | utf8mb4_0900_ai_ci`。
4. **切换库**：左侧 `SCHEMAS` 面板刷新，右键 `DcwCncStation` → `Set as Default Schema`。
5. **执行建表**：打开 `02_schema_full.sql`，确认上方 Schema 下拉已选中 `DcwCncStation`，全量执行（`Ctrl+Shift+Enter`）。执行完成后 `SCHEMAS` 下应出现 8 张表。
6. **执行基线脚本**：打开 `03_migration_history_baseline.sql`，全量执行，结果集应返回 3 行迁移记录。
7. **执行校验脚本**：打开 `04_verify.sql`，全量执行，逐项核对第 8 章的期望值。

Navicat 操作类似：`连接` → `新建查询` → 打开脚本 → `运行`（注意先在连接属性中选定 `DcwCncStation` 数据库，否则脚本会作用到默认库）。

> **重要**：图形化客户端默认可能整段执行，务必确认当前选中库为 `DcwCncStation`，避免把表建到 `ShutteringStation` 或 `mysql` 库中。

## 6 方式三：EF Core 设计时命令生成建库脚本

适用于开发/交付人员需要"从代码重新推导 DDL"的场景。

### 6.1 设计时连接串在哪里取

`CncWallStation/EntityFrameworkCore/AppDbContextFactory.cs` 已统一改为读取项目 `appsettings.json` 的 `ConnectionStrings:Default`，与运行期完全一致：

- 查找顺序：当前工作目录 → 程序集输出目录，逐层上溯查找 `appsettings.json`；
- 可临时覆盖，无需改代码：

```powershell
$env:DCW_DB_CONNECTION = "Server=10.33.120.30;Port=3306;Database=DcwCncStation;User ID=root;Password=***;Charset=utf8mb4;"
```

> 历史坑位：`AppDbContextFactory` 曾硬编码 `Server=10.34.120.31`，与 `appsettings.json` 的 `10.33.120.30` 不一致，设计时命令会连错服务器。该问题在本版本已修复。

### 6.2 生成全量建库 DDL

```powershell
cd d:/Works/workspace/projects/WorkStations/xBraceWall/DCW/CncWallStation

# 安装/升级设计时工具（首次或版本不一致时）
dotnet tool install --global dotnet-ef

# 依据模型快照生成全量建表脚本
dotnet ef dbcontext script -o ../documents/sql/02_schema_full.sql
```

生成结果需要人工核对以下要点（与 `AppDbContext.OnModelCreating` 逐条比对）：

| 核对项 | 期望 |
| --- | --- |
| 表数量 | 8 张（`Project`、`Wall`、`ValidationError`、`DataCheckRecord`、`PlcInstruction`、`Opc`、`MachiningException`、`MachiningRecord`） |
| `Wall` 索引 | 15 条（含主键），索引名与代码 `HasDatabaseName` 完全一致 |
| 大文本列 | `Wall.BimJsonData`、`Wall.MomJsonData`、`MachiningException.Description` 为 `MEDIUMTEXT` |
| `timestamp` 列 | 必须带 `DEFAULT CURRENT_TIMESTAMP` |
| 外键 | 7 条，且全部 `ON DELETE CASCADE`（`Opc` 表按模型定义无外键） |

> 注意：`dotnet ef dbcontext script` 输出的是 `CREATE TABLE`（无 `IF NOT EXISTS`）、索引独立 `CREATE INDEX` 语句，且首行带 `ALTER DATABASE CHARACTER SET utf8mb4;`。仓库中的 `02_schema_full.sql` 已在此输出基础上改为幂等写法（`CREATE TABLE IF NOT EXISTS` + 索引内联 + 显式排序规则），二者结构等价。

### 6.3 为什么不使用 `dotnet ef database update`

`Migrations/` 目录下只有 3 个**增量**迁移，**没有初始建表迁移**：

- `20260519083754_AddDataCheckSupport`（`ValidationError` 加列 + 建 `DataCheckRecord`）
- `20260713022100_AddPlcInstructionSide`（`PlcInstruction` 加 `Side` 列与索引）
- `20260727022215_AddPerformanceIndexes`（`Wall` 加 2 个复合索引）

若在空库上执行 `dotnet ef database update`，第一条迁移会去 `ALTER` 一个不存在的 `ValidationError` 表，直接失败。因此空库一律使用 `02_schema_full.sql` 建全量结构，再用 `03_migration_history_baseline.sql` 登记已应用迁移。

### 6.4 后续新增迁移的标准流程

基线建立后，开发人员修改模型（实体或 `OnModelCreating`）时：

```powershell
dotnet ef migrations add <迁移名>          # 生成增量迁移
dotnet ef migrations script <上一个> <当前>  # 生成可评审的升级 SQL，交给现场执行
```

现场按评审后的升级 SQL 执行，并同步更新 `__EFMigrationsHistory`（或由 DBA 审核后使用 `database update`）。**生产库禁止直接 `database update`。**

## 7 应用启动时的自动建表机制

了解这段机制可以避免重复建库或误判"程序自动建了库"。

### 7.1 开关：`Database:AutoInitialize`

`appsettings.json` 中的 `Database:AutoInitialize` 决定应用启动时是否自动建库建表：

```json
{
  "ConnectionStrings": {
    "Default": "Server=10.33.120.30;Port=3306;Database=DcwCncStation;User ID=root;Password=<密码>;Charset=utf8mb4;Connection Timeout=30;"
  },
  "Database": {
    "AutoInitialize": false
  }
}
```

| 取值 | 启动行为 | 适用场景 |
| --- | --- | --- |
| `false`（当前交付值） | **完全跳过**建库、建表与升级脚本，只建立连接池，不执行任何 DDL | 生产工位；库结构由本手册的 SQL 脚本负责 |
| `true` | 执行 7.2 描述的 `EnsureCreated` + 手写 DDL 流程 | 开发调试、首次拉起环境 |
| 缺省或值非法 | 按 `true` 处理，并写一条 Warning 日志 | 兼容升级前的旧配置文件 |

> 开关从 `appsettings.json` 读取，也可用环境变量覆盖（如 `Database__AutoInitialize=true`）。修改后需重启客户端生效。

### 7.2 开关为 `true` 时的行为

`CncWallStation/Services/Application/DatabaseInitializerHostedService.cs` 在应用启动时（`IHostedService.StartAsync`）执行：

1. `db.Database.EnsureCreatedAsync()` —— 库不存在则**自动建库并建表**；库已存在则**什么都不做**（不比对结构、不改结构）。
2. 随后执行一组手写 `CREATE TABLE IF NOT EXISTS`（`PlcInstruction`、`Opc`、`MachiningException`、`MachiningRecord`）与若干 `ALTER TABLE`（为旧库补 `Side` 列、`Registrant` 列、异常报告新增列等）。
3. 连接类错误（超时、网络抖动）会按 2 秒、5 秒重试，最多 3 次；权限错误（`AccessDenied` / `UnknownDatabase`）不重试，直接抛错。

### 7.3 结论与日志判读

- **交付配置（`false`）下，应用启动不执行任何 DDL**，库结构完全由本手册的脚本决定，可以安全反复启动。
- 该模式下运行账号**不需要 `CREATE DATABASE` / `ALTER` 权限**，只需 `SELECT/INSERT/UPDATE/DELETE`（`index` 相关权限仅在建库账号上需要）。
- 关闭自动初始化后，若库或表缺失，程序启动会正常进入主界面，但业务查询报错（`Table 'dcwc...' doesn't exist`）——请先按下文执行建库脚本。
- 日志判读（`logs/log-YYYYMMDD.txt`）：
  - `数据库自动初始化已禁用（Database:AutoInitialize = false），跳过建库/建表与升级脚本` → 开关生效，符合生产预期；
  - `开始初始化数据库...` / `数据库初始化完成` → 走了自动建表流程（`true`）；
  - `数据库初始化第 x/3 次尝试失败` → 网络或 MySQL 反查主机名耗时过长。

## 8 建库结果校验

### 8.1 自动校验

执行 `04_verify.sql`，逐项核对下表（全部脚本执行成功后，实测结果与本表一致）：

| 校验项 | 期望结果 | 实测（2026-10-21） |
| --- | --- | --- |
| 库字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci` | OK |
| 表数量 | 9（8 张业务表 + `__EFMigrationsHistory`） | 9 → OK |
| `Wall` 索引数 | 15（含主键） | 15 → OK |
| 外键数量 | 7，且全部 `CASCADE` | 7 / 7 → OK |
| `MEDIUMTEXT` 列 | `Wall.BimJsonData`、`Wall.MomJsonData`、`MachiningException.Description` | 3/3 → OK |
| `timestamp` 默认值 | 8 个 `timestamp` 列全部 `CURRENT_TIMESTAMP` | 8/8 → OK |
| 迁移基线 | 3 行 | 3 → OK |

## 9 常见故障排查

| 错误码 / 现象 | 可能原因 | 处理办法 |
| --- | --- | --- |
| `ERROR 2003 (HY000): Can't connect to MySQL server` | 网络不通、IP/端口错误、防火墙拦截、MySQL 未启动 | 用 `Test-NetConnection` 复测 2.3；核对 `appsettings.json` 的 `Server`/`Port` |
| `ERROR 1045 (28000): Access denied for user` | 密码错误、账号无该主机授权、`MYSQL_PWD` 含特殊字符被截断 | 交互式 `-p` 重新输入；确认账号对客户端网段授权；Windows 下确认密码未被 PowerShell 转义 |
| `ERROR 1044 (42000): Access denied for user ... to database` | 账号无 `CREATE`/目标库权限 | 按 2.4 授权 |
| `ERROR 1049 (42000): Unknown database` | 未执行 `01_create_database.sql`，或库名拼写不一致 | 先建库；核对库名 `DcwCncStation` |
| `ERROR 1215 (HY000): Cannot add foreign key constraint` | 建表顺序错误（父表未建）、引擎非 InnoDB、列类型/字符集不一致 | 严格按 01→02 顺序执行；确认引擎为 InnoDB |
| `ERROR 1075 / 1005` | 表已存在且结构不同（历史残留表） | 用 `SHOW CREATE TABLE` 比对，必要时备份后清理该表再重建 |
| `ERROR 1366 (HY000): Incorrect string value` | 库/表/连接字符集不是 utf8mb4 | 核对库排序规则；连接串必须含 `Charset=utf8mb4` |
| `ERROR 1267 Illegal mix of collations` | 混用了 `utf8mb4_general_ci` 与其他排序规则 | 全库统一 `utf8mb4_0900_ai_ci`（本手册脚本已固定） |
| `ERROR 1290 --secure-file-priv` | 用 `LOAD DATA` 导入被限制 | 建库流程不涉及，如遇导入改用客户端工具 |
| 应用日志 `DatabaseAccessDenied` | 运行账号无目标库权限 | 按 2.4 授权，或修改连接串账号 |
| 应用日志 `Connect Timeout expired` | MySQL 反查客户端主机名超时 | 服务器启用 `skip_name_resolve`，或按 `DatabaseInitializerHostedService` 的重试策略重试 |
| 时间列显示相差 8 小时 | MySQL 会话时区与应用时区不一致 | 建表不涉及时区；如需统一，服务器 `default-time-zone='+08:00'` |

> **连接串不一致历史问题**：`AppDbContextFactory.cs` 曾硬编码 `10.34.120.31`（工厂服务器），与 `appsettings.json` 的 `10.33.120.30` 不同。若发现 `dotnet ef` 命令连到了非预期服务器，先检查是否误用了旧版本代码或残留的 `DCW_DB_CONNECTION` 环境变量。

## 10 备份、恢复与回滚

### 10.1 备份

建库前若目标库已存在，**必须先备份**：

```powershell
mysqldump -h 10.33.120.30 -P 3306 -u root -p `
          --single-transaction --routines --triggers `
          --default-character-set=utf8mb4 `
          DcwCncStation > DcwCncStation_backup_20261021.sql
```

### 10.2 恢复

```powershell
mysql -h 10.33.120.30 -P 3306 -u root --default-character-set=utf8mb4 DcwCncStation `
      -e "source DcwCncStation_backup_20261021.sql"
```

> `mysqldump` 默认不含 `CREATE DATABASE`。恢复前需先执行 `01_create_database.sql` 建好空库。

### 10.3 回滚（删除整库）

`documents/sql/05_drop_database.sql` 内容为：

```sql
DROP DATABASE IF EXISTS `DcwCncStation`;
```

执行前必须满足：

1. 已完成 10.1 备份并验证备份文件可读；
2. 已停止所有 CncWallStation 客户端与相关服务；
3. 已获得现场负责人书面确认。

删除后需按第 4 章重新建库，历史业务数据只能靠备份恢复。

### 附录 D 连接串模板

`CncWallStation/appsettings.json`：

```json
{
  "ConnectionStrings": {
    "Default": "Server=10.33.120.30;Port=3306;Database=DcwCncStation;User ID=root;Password=<密码>;Charset=utf8mb4;Connection Timeout=30;"
  },
  "Database": {
    "AutoInitialize": false
  }
}
```

要求：

- 必须包含 `Charset=utf8mb4`；
- `Server`、`Port`、`Database` 与第 2.1 节一致；
- 生产环境将 `User ID` / `Password` 替换为专用账号；
- `Database:AutoInitialize` 生产环境置 `false`，由本手册脚本负责库结构（见第 7 章）；
- 修改后需重启客户端程序生效。
